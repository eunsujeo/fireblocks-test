# DAWBC / Wallet SDK 흐름 비교

결과물은 `docs/flow-comparison/index.html`이다. 두 구조를 같은 단계의 행에 나란히 배치한다.
정상 입금, 미확인 입금, 별단입금 집금, 집금 전·후 반환, 회사 입금을 비교한다.
상단의 `← Wallet SDK로 돌아가기`는 같은 창에서 SDK 첫 화면으로 이동한다. 파일 직접 열기와 JavaScript 없는 환경에서도 동작한다.

- `build.py`: 비교 본문, 근거 링크, HTML 생성. 생성 HTML은 직접 편집하지 않는다.
- `delivery.py`: SDK가 책임질 Queue 대응 기능과 CORE 수신·처리 경계, 검증 조건.
- `differences.py`: 22개 단계의 짧은 좌우 차이와 CORE 연동 확인 사항. 공통 2개 단계에는 표시하지 않는다.
- `evidence.py`: 24개 단계별 근거 매핑. 모달에는 선택한 단계의 근거만 표시한다.
- `sequences.py`: 단계별 메시지 순서와 SVG 생성. 원문에 없는 흐름은 미제공 안내로 표시한다.
- `sdk_sweep.py`: SDK 집금 원문의 두 도식을 읽어 9개 참여자·30개 호출·4개 주석과 실행 구간을 모두 그린다.
- `style.css`: 좌우 비교표·시퀀스 모달, 작은 화면 가로 스크롤, 가로 방향 인쇄.
- `reader.js`: 차이만 보기, 단계 클릭 시 시퀀스 모달, 이전·다음·확대·전체 화면·좌우 이동, SDK 구간·호출 탐색, 포커스 복구와 인쇄.
- `diagram-zoom.js`: 정상 입금의 자동스윕에서 DAWBC·SDK 각각의 확대 모달. 그림 또는 헤더의 확대 모달 버튼으로 열고, 10~400% 배율·원본 크기·가로 맞춤과 가로·세로 스크롤을 제공한다. 호출 문구 클릭은 기존 탐색·요구사항 동작을 유지한다. 원래 SVG를 잠시 옮겨 표시하며 닫기·Escape·바깥 클릭·인쇄 시 원위치와 비교 화면 상태를 복구한다.
- `participant-headers.js`: 비교·확대 모달에서 원래 참여자 행이 화면 위로 사라졌을 때만 이름 행을 고정한다. SVG 참여자 좌표·폭·배율·색상에 맞춰 표시하고, 가로 스크롤·단계 변경·모달 이동·창 크기 변경에 동기화한다. 원래 행과 스크롤 공간은 유지하며 인쇄·JavaScript 없는 환경에서는 기존 SVG를 읽는다.
- `verify.cjs`: 정렬, 필터, 로컬 근거 새 창, 모바일, 인쇄, JavaScript 없는 읽기 검증.
- `verify_diagram_zoom.cjs`: 양쪽 확대 모달·키보드·배율·SVG 보존·복귀 상태·320/390px 스크롤·인쇄 복구 검증.
- `verify_participant_headers.cjs`: 고정 행 표시 조건·양쪽 생명선 정렬·가로 스크롤·확대·320/390px·복귀·단계 변경·인쇄 검증.

```sh
python3 scripts/flow-comparison/build.py
node scripts/flow-comparison/verify.cjs
node scripts/flow-comparison/verify_diagram_zoom.cjs
node scripts/flow-comparison/verify_participant_headers.cjs
```

검증은 기존 Playwright 설치를 사용한다. 필요하면 `PLAYWRIGHT_MODULE`, `CHROME_BIN`을 지정한다.
결과·캡처는 `/tmp/flow-comparison-verification/`에 저장한다.

기준은 원장 v0.1.4 PDF와 2026-09-11에 보관한 SDK v1.1.0 문서다. 오른쪽 열은 SDK 문서의 계약과
CORE 연동 검토를 함께 설명하며, 실제 구축 완료나 SDK 최신 배포 상태를 뜻하지 않는다.
특히 UPDATED·트래블룰·KYT 미구현 표기, 예약 적용 범위의 상충 설명, 목적지 태그 통제의
미제공 표기를 SDK 근거와 함께 유지한다. DAW PDF에 없는 직접 반환 시퀀스를 만들어 넣지 않는다.

본문은 CSS·JavaScript를 포함한 HTML 한 파일이다. 서버나 ZIP 없이 열 수 있다.
근거 새 창은 `docs/ledger/`와 `docs/wallet-sdk/`, 자동스윕 실행은 `docs/api/`와 `docs/design/`도 사용한다.
근거까지 전달하려면 해당 폴더의 상대 위치를 유지한다.

2026-09-11: 6개 흐름·24개 비교 단계, 로컬 링크 132개(고유 경로 26개)·브라우저 기능 20개 통과. 단계 모달의 좌우 SVG 48개(상세 미제공 안내 포함), 문구 잘림·키보드·모바일·단계별 근거·읽던 위치 복구를 확인했다. SDK 자동스윕은 원문 메시지·순서·주석·참여자·실행 구간 보존을 검증한다.
320·390·768px 화면에서 본문 넘침 없이 비교표 안에서 가로 탐색을 확인했다.
PDF 해시 유지, 외부 요청·브라우저 오류 0건. 프로젝트 문서 안내에서 연결한다.

자동스윕의 SDK 시퀀스는 원문의 두 도식을 순서대로 연결한 전체 흐름이다. 정책 엔진·저장소·이벤트 스트림·Co-Signer·뒷단 플랫폼을 각각 표시하고 원문의 실선·점선을 유지한다. 나란히 보기에서는 전체 가로 폭을 미리 보고, SDK 크게에서는 해당 도식만 넓게 펼쳐 읽는다. 다른 단계는 기존 요약이며 실선은 요청·내부 처리, 점선은 응답·이벤트, 황색 점선은 미확정 연동이다. JavaScript를 끄면 단계별 비교 본문과 근거 링크는 계속 읽을 수 있고 모달 버튼은 숨긴다.

정상 입금의 마지막 단계는 자동스윕 — 받는주소 → 보내는주소다. 자동스윕의 업무 방향은 원장 설계, 실행 상세는 현행 BCM API·배치 설계에 근거하며 같은 단계의 표와 시퀀스에서 함께 보여준다. 다른 경로인 보내는주소 → 콜드월렛 시퀀스를 옮겨 쓰지 않는다. 사용자 요청에 따라 별도 배치 보충 표·모달은 없앴다. BCM의 POST /sweeps, allowance 준비, batchSweep·transferFrom, 항목별 결과와 완료 확인을 SDK의 입금 건별 API와 나란히 비교한다. SDK 정책 검사는 접수 후 진행하며 일회용 서명 허가 발급과 실제 서명을 구분해 설명한다. SDK의 온체인 배치 지원은 문서에서 확인되지 않은 항목으로 남긴다.

일반 모달은 최대 1540×1100px, 나란히 도식은 최대 1420px로 기본 크기를 제한한다. 전체 화면으로 펼쳐도 도식을 자동으로 늘리지 않는다. 참여자 이름 복제 행과 원래 헤더를 숨기던 처리를 제거해 불필요한 여백을 복구했다.

자동스윕은 나란히 보기에서 양쪽 도식의 전체 가로 폭을 표시한다. SDK 크게·DAWBC 크게는 선택한 도식만 같은 창에서 넓게 펼치며, 나란히 보기로 돌아온다. SDK 메시지 글자는 14px이며 100~400% 확대를 지원한다. 모바일의 크게 보기에서는 원래 도식 폭을 유지하고 스크롤한다. 호출 탐색은 기본으로 접고, 펼치면 구간·이전/다음 호출 이동과 원문 내용을 제공한다. 원문 30개 호출·9개 참여자는 그대로 보존한다.

사용자 화면 회귀를 1440·1920·3766px에서 재현해 일반 도식 배율, 원래 참여자 헤더, 자동스윕 가로 잘림, SDK 크게의 실제 확대와 비교 화면 복귀를 검증했다. 모바일 탐색과 전체 화면·400% 확대를 포함해 브라우저 기능 20개가 통과했다.

다이어그램 위의 “이 단계의 차이”는 DAWBC·Wallet SDK를 각각 한 문장으로 대비하고 CORE 연동 확인 사항을 한 줄로 붙인다. 기존 표와 단계별 근거 범위 안에서 작성하며 미구현·미확인 상태를 유지한다. 설명은 도식과 함께 스크롤되고 전체 화면·단독 크게 보기에서도 유지한다. 원문 호출과 주석은 바꾸지 않는다.

SDK 교체 시에도 유지할 CORE 원장·어드민·서비스 업무는 “CORE 유지” 문구로 표시한다. SDK 문서의 실제 요청·응답·웹훅과 구분하며, 적용 시점과 미확정 결과 수신은 황색으로 표시한다. CORE에서 SDK로 보내는 Confirmed/Finalized 잔고 반영 API를 만들지 않는다. UPDATED 미구현과 집금 후 반환 경로 미확정은 유지하면서 공통 CORE 업무를 생략하지 않는다. 자동스윕 SDK 원문 30개 호출은 그대로 유지한다.

SDK eventId 요구사항은 시퀀스 위 안내와 클릭 가능한 eventId 문구에서 상세 모달로 연다. 개별 이벤트 식별·원장 중복 방지·양측 이력 대조가 목적이며, 최초 발급·보관, 재전송 시 ID 유지, 새 갱신 시 새 ID, SDK 발행 범위 내 유일성을 요구한다. 순서 판정은 별도 계약이다. SDK 지원 미확인 및 지원 전 depositId+eventType의 적용 범위도 표시한다. 입금 시퀀스의 중복 제거는 eventId 요구사항으로 수정해 제공 기능으로 단정하지 않는다. 로컬 링크 132개·앵커 22개와 기존 브라우저 검증 20개 통과.

상세 모달은 기존 시퀀스 위에서 열리며 Escape·닫기·바깥 클릭으로 상세만 닫는다. 시퀀스의 확대·스크롤·선택 화면과 트리거 포커스를 복구한다. eventId 도식 문구는 키보드 Enter/Space로도 열 수 있다. 본문 상세는 한 벌만 유지하고 JavaScript 실행 시 모달로 이동한다. JavaScript가 없거나 인쇄할 때는 전체 요구사항을 읽을 수 있다. 상단 메뉴와 기존 #sdk-event-id 링크는 같은 모달로 연결한다.

Queue 대응 요구사항은 관련 시퀀스의 버튼 또는 SDK의 전달 보장 문구에서 상세 모달로 연다. 지원 기능으로 단정하지 않고 SDK 영속 보관·재전송·순서·실패 격리·발행 및 전달 이력 조회를 요구한다. CORE 수신 영속화 후 2xx와 원장 반영 완료를 구분한다. CORE가 완료를 자체 기록·추적하고 미처리·실패 건을 재처리한다. SDK 완료 회신은 선택 사항으로 별도 협의한다. Queue 제거는 SDK 기능과 CORE 경계의 장애 검증 후 판단한다. eventId·Queue 내용 전환, 기존 시퀀스 복구, 바로가기, 인쇄·JS 없는 읽기를 포함해 20개 브라우저 검증을 통과했다.

SDK v1.1.0 반영: 공통 계약에 Vault 이체의 SETTLING·양쪽 잔액 반영 후 통지를 추가했다. 정상 자동스윕 원문 30개 호출은 유지하고 정책·승인 관련 5개 단계 위에 현재 실 정책 서버 미연결·동기 자동 승인, Wallet Admin 승인 API 고정 응답을 표시한다. 집금 기록 생성 시점과 완료 통지 설명의 상충은 새 결과 읽기·변경 이력과 함께 확인 사항으로 남긴다.

Outbox ⓘ는 마우스 올리기·키보드 포커스에서 짧은 툴팁을 표시하고 클릭·Enter·Space로 BCM 흐름 모달을 연다. `outbox.py`는 현행 BCM의 DB 원자 저장·Kafka 발행·CORE 완료 확인 시퀀스와 실패 처리를 생성하고, `tooltips.js`는 툴팁과 중첩 모달을 제어한다. Kafka 발행 성공과 CORE 업무 완료를 구분하며 SDK 교체안의 선택적 완료 회신과 혼동하지 않게 명시한다. 모바일에서는 도식 안에서 가로 이동하며, 닫기·Escape·바깥 클릭 후 기존 Queue 모달·포커스·스크롤을 유지한다. JavaScript가 없으면 본문 앵커와 title 설명을 유지하며 인쇄에는 상세 흐름을 포함한다. `verify_tooltips.cjs`로 데스크톱·320/390px·중첩 복귀·인쇄·JavaScript 없는 읽기를 검증한다.

새 기술 용어·약어를 설명 없이 추가하지 않는다. 쉬운 말로 풀어 쓰거나 `terms.py`에 정의를 등록해 툴팁을 붙인다. Queue 상세의 DLQ·Inbox·relay·멱등·원자적·2xx·4xx·5xx에 적용했다. 일반 용어는 클릭·포커스·마우스 올리기로 설명만 열고, Outbox만 상세 다이어그램 모달로 연결한다. DLQ는 SDK에 요구하는 실패 보관 방식의 예시이며 제공 여부 미확인임을 유지한다.
