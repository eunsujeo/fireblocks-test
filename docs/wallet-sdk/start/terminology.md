_읽는 사람: 파트너사 개발자. 이 사이트에서 쓰는 도메인 용어의 색인입니다._

이 페이지는 용어마다 한 줄 정의와 자세한 설명이 있는 페이지를 안내합니다. 다른 페이지가 용어를
처음 쓸 때 붙이는 한 줄은 여기의 문구를 그대로 복사한 것입니다.

색인의 범위는 파트너사가 이 사이트를 읽다가 만나는 용어입니다. 구현팀만 쓰는 항목도 표에는 두되,
정의 위치를 「설계 기록(내부)」로만 적고 이 사이트에 페이지를 두지 않습니다.

같은 말을 두 곳에서 정의하면 언젠가 갈립니다. 기준 문구를 여기 한 곳에 두고 다른 페이지가 그것을
복사하는 것이 그것을 막는 방법입니다.

## 미승격 표시

정의 위치가 `미승격`인 용어는 그 정의가 아직 이 사이트에 없다는 뜻입니다. 페이지 자체가 없는 것도
있고, 페이지는 있는데 그 용어를 아직 안 담은 것도 있습니다. 그때까지의 기준 문서는 저장소의 설계
문서이고, 페이지가 생기는 대로 이 표를 채웁니다.

## 격리 컨테이너

격리 컨테이너는 세 계층입니다.

| 용어 | 무엇인지 | 정의 위치 |
|---|---|---|
| JV | 플랫폼을 운영하는 합작 법인입니다. Workspace 생성과 시드 정책의 권한 뿌리입니다 | 미승격 |
| Workspace | Wallet SDK를 도입한 회사 하나입니다. 최상위 격리 컨테이너입니다 | [계정 계층](/accounts-wallets/accounts) |
| Tenant | Workspace 아래에서 Account를 묶는 계정 체계 하나입니다. 파트너 대상 API의 격리 키입니다 | [계정 계층](/accounts-wallets/accounts) |
| 파트너사 | Wallet SDK를 도입한 회사, 곧 Workspace 하나입니다. 이 사이트에서 그 회사를 부르는 말은 이것 하나입니다 | [계정 계층](/accounts-wallets/accounts) |
| Account | 그 서비스의 최종 사용자 한 명을 wallet 안에서 대리하는 virtual 사용자입니다 | [계정 계층](/accounts-wallets/accounts) |
| `accountId` | Wallet SDK가 발급해 Account를 지칭하는 값입니다. 스코프 키가 아닙니다 | [표면과 인증](/start/authentication) |
| `referenceId` | 파트너사가 발급한 사용자 식별자입니다. 유일성은 Tenant 안에서만 성립합니다 | [계정 계층](/accounts-wallets/accounts) |
| 스코프 키 | 인증이 확정하는 격리 식별자입니다. 요청이 싣지 않습니다 | [표면과 인증](/start/authentication) |
| 스코프 축 | 어떤 데이터가 어느 스코프 키로 격리되는지의 분류입니다 | 설계 기록(내부) |

## 표면과 인증

표면마다 인증이 확정하는 것이 다릅니다.

| 용어 | 무엇인지 | 정의 위치 |
|---|---|---|
| 표면 | 계약 소유자와 인증 방식이 하나로 정해지는 API 경로 묶음입니다 | [표면과 인증](/start/authentication) |
| API 키 | 파트너사가 파트너 대상 API를 부를 때 제시하는 인증 수단입니다 | [표면과 인증](/start/authentication) |
| 어드민 세션 | 로그인과 2단계 인증을 지나 받는 불투명 크리덴셜입니다 | [표면과 인증](/start/authentication) |
| AdminUser | 운영자 표면을 부르는 사람 주체입니다. API 키와 달리 사람을 식별합니다 | 미승격 |
| Policy Server | 승인·정책 평가와 어드민 역할을 소유하는 별도 시스템입니다 | 미승격 |
| 소속 스코프 | 어드민 계정이 속한 스코프 하나입니다. `platform` 또는 `workspace:{id}`이고, 계정의 모든 부여는 소속과 같아야 합니다 | 설계 기록(내부) |
| 문 | 어드민 표면의 진입 경로 둘입니다. platform 문은 `/platform/**` 아래 표면이고 워크스페이스 문은 접두 없는 표면입니다. 세션의 소속과 어긋나면 거부합니다 | 설계 기록(내부) |
| 릴레이 | WalletAdmin이 콘솔에서 받은 어드민 세션 자격을 저장하지 않고 그대로 Policy Server에 실어 보내는 것입니다 | 설계 기록(내부) |
| introspection | 자격을 받은 쪽이 발급자에게 그 세션의 주체·소속·부여를 묻는 것입니다. 발급자가 답하지 않으면 그 표면은 닫힙니다 | 설계 기록(내부) |
| 스텝업 | 어드민 세션 위에 행위 단위로 본인을 다시 증명하는 절차입니다. 챌린지와 TOTP로 이뤄지고 권한은 전후로 같습니다 | 설계 기록(내부) |

## 자산과 지갑

자산은 어느 네트워크의 어느 토큰인지로 구분하고 Vault와 Wallet에 담깁니다.

| 용어 | 무엇인지 | 정의 위치 |
|---|---|---|
| Vault | Wallet의 그룹입니다 | [지갑 계층](/accounts-wallets/wallets) |
| Wallet | 토큰 하나를 담습니다. 온체인 주소가 여기 붙습니다 | [지갑 계층](/accounts-wallets/wallets) |
| WorkspaceVault · WorkspaceWallet | Workspace에 귀속된 vault와 토큰별 지갑입니다 | [지갑 계층](/accounts-wallets/wallets) |
| AccountVault · AccountWallet | Account에 귀속된 vault와 토큰별 수취 지갑입니다 | [지갑 계층](/accounts-wallets/wallets) |
| vault 태그 | 파트너사가 vault 용도를 정의하는 값입니다. 앱은 해석하지 않습니다 | [지갑 계층](/accounts-wallets/wallets) |
| Network | 블록체인 네트워크입니다. 계열에 따라 주소 체계가 갈립니다 | [카탈로그](/accounts-wallets/catalog) |
| Token | Network 위의 자산입니다. Wallet이 담는 단위입니다 | [카탈로그](/accounts-wallets/catalog) |
| 회사 외부 지갑 | Workspace가 소유하나 이 시스템 밖에 있는 지갑입니다 | [이동 종류](/fund-flows/movements) |
| 주소록 | 주소에 등재 근거를 붙이는 장부입니다. 계정 주소록과 워크스페이스 주소록으로 갈립니다 | [주소록](/fund-flows/address-book) |
| 화이트리스트 | 출금 통제에서 부르는 주소록의 다른 이름입니다. 등재 여부는 정책 입력이지 거절 사유가 아닙니다 | [주소록](/fund-flows/address-book) |
| 소유 증명 | 개인 지갑을 주소록에 올리기 전에 최종 사용자가 그 키로 서명해 보이는 절차입니다 | [주소록](/fund-flows/address-book) |
| 소유 증명 챌린지 | 등록 직전에 서버가 발급하는 일회용 서명 대상입니다 | [주소록](/fund-flows/address-book) |
| Vault 소유 해석 | vault 식별자 하나로 소유 workspace와 tenant를 확정하는 조회입니다 | [PIP](/policy/runtime/pip) |

## 자금 이동

자금 이동은 일곱 가지뿐입니다.

| 용어 | 무엇인지 | 정의 위치 |
|---|---|---|
| 동결 | 입금을 확정 시 fail-closed로 잡아 두는 상태입니다 | [자금 동결](/fund-flows/release) |
| 해제 | 동결을 푸는 것입니다. 언제나 명시적 요청입니다 | [자금 동결](/fund-flows/release) |
| 입금 갱신 통지 (`DEPOSIT_UPDATED`) | 확정 뒤에 트래블룰 매핑이나 KYT 결과가 붙을 때마다 그 순간까지의 정보를 전부 실어 보내는 통지입니다 | [입금](/fund-flows/deposit) |
| 사전 확인 · 사후 확인 | 동결 해제 판단 재료를 온체인 확정 이전에 얻는 것(트래블룰·주소록)과 이후에 얻는 것(AML·FDS·KYT)으로 나눈 구분입니다 | [입금](/fund-flows/deposit) |
| 가용 잔액 | 온체인 잔액에서 동결분과 진행 중 출금 예약분을 뺀 값입니다 | [출금](/fund-flows/withdrawal) |
| 자금 귀속 | 그 자금이 Account 것인지 Workspace 것인지입니다. 무엇이 격리되는지를 정합니다 | [이동 종류](/fund-flows/movements) |
| 계정 지갑 입금 (`awd-`) | VASP·개인 지갑에서 계정 지갑으로 들어온 자금입니다. 거부할 수 없고 확정되면 동결로 받습니다 | [입금](/fund-flows/deposit) |
| 워크스페이스 지갑 입금 (`wwd-`) | 회사 외부 지갑에서 워크스페이스 vault로 들어온 자금입니다. 거부할 수 없고 확정되면 동결로 받습니다. 해제는 운영자의 독립 요청입니다 | [이동 종류](/fund-flows/movements) · [자금 동결](/fund-flows/release) |
| 집금 (`swp-`) | 계정 지갑 자산을 워크스페이스 vault로 모으는 이동입니다 | [집금](/fund-flows/sweep) |
| Vault 이체 (`wvt-`) | 워크스페이스 vault 사이의 이동입니다 | [Vault 이체](/fund-flows/vault-transfer) |
| 계정 귀속 출금 (`wwac-`) | 워크스페이스 vault에서 나가는 최종 사용자 귀속 출금입니다 | [출금](/fund-flows/withdrawal) |
| 자기 귀속 출금 (`wwsf-`) | 회사 외부 지갑으로 나가는 회사 자기 자금 출금입니다 | [출금](/fund-flows/withdrawal) |
| 계정 지갑 출금 (`aww-`) | 계정 지갑에서 직접 나가는 이동입니다. 알려진 용도는 오입금 반환입니다 | [출금](/fund-flows/withdrawal) |
| 통지 | 온체인 이벤트를 파트너사에 보내는 아웃바운드 호출입니다. 웹훅에 실리는 내용물입니다 | [웹훅](/fund-flows/webhooks) |
| 웹훅 | 통지를 나르는 채널입니다 — 파트너사가 등록한 URL로의 HTTP 호출입니다 | [웹훅](/fund-flows/webhooks) |
| 대사 | 기록과 뒷단 플랫폼의 사실이 어긋난 것을 바로잡는 2차 방어입니다 | 미승격 |
| 트래블룰 | 가상자산 이전 시 송·수신 정보를 사업자끼리 교환하는 규제 의무입니다 | [에코시스템](/#함께-제공하는-모듈) |

## 정책 엔진의 역할

| 용어 | 무엇인지 | 정의 위치 |
|---|---|---|
| 정책 엔진 | 자금을 움직이는 요청이 서명 인프라로 가기 전에 그 요청을 심사하는 별도 시스템입니다. 특정 컴포넌트가 아니라 아래 역할 전체를 가리킵니다 | [구조](/policy/architecture) |
| Orchestrator | 판단 요청을 접수하고 입력 문서를 조립하고 PIP 수집과 obligation 루프를 조율하는 정책 엔진의 앞단입니다. 판정 자체는 하지 않습니다 | [구조](/policy/architecture) |
| 평가기(PDP) | 완성된 입력 문서를 평가해 결정을 내는 역할입니다. 밖을 부르지 않습니다 | [구조](/policy/architecture) |
| PIP | 판단에 필요한 사실을 평가 시점에 읽어 오는 수집 경로입니다. Orchestrator 안의 어댑터 계층입니다 | [PIP](/policy/runtime/pip) |
| PAP | 룰을 저작·검증·발행하는 경로 전체를 부르는 이름입니다 | [저작과 발행](/policy/workflow) |
| PEP | 서명 인프라 콜백을 받아 인가 대조를 Orchestrator에 넘기는 지점입니다 | [서명 게이트](/policy/signing-gate) |
| Co-Signer | 서명 인프라 쪽에서 서명 직전에 정책 엔진 콜백으로 승인을 묻는 구성 요소입니다 | [서명 게이트](/policy/signing-gate) |
| Wallet 서버 | 파트너 대상 API를 받아 정책 엔진에 판단을 묻고 서명 인프라에 제출하는 Wallet SDK의 서버 컴포넌트입니다 | [구조](/policy/architecture) |
| 서명 인프라 | 키를 보관하고 트랜잭션에 서명하는 뒷단 플랫폼의 서명 부분입니다. Wallet SDK 단독으로는 서명이 성립하지 않습니다 | [시작하기](/start) |
| 입력 문서 | Orchestrator가 요청·환경·PIP 결과를 모아 평가기에 넘기는 완성된 평가 입력입니다 | [평가의 순간](/policy/runtime/evaluation) |
| 결과 스냅샷 | PIP가 돌려준 값을 참조 id·수집 시각·출처와 함께 고정한 기록입니다. PII를 담지 않습니다 | [PIP](/policy/runtime/pip) |
| 서명 연산 | 정책 엔진이 심사하는 첫 영역입니다. `withdrawal`·`custody_transfer`·`sweep`·`contract_call`·`typed_signature` 다섯 연산의 허가 요청입니다 | [룰 명세](/policy/rule/reference) |
| 어드민 액션 | `operation`이 `admin_action`인 요청입니다. 개별 액션은 `payload.action`으로 가르고, 워크스페이스 스코프 액션은 액션 카탈로그의 `domain`이 `"2"`입니다 | [룰 명세](/policy/rule/reference) |
| 정책 변경 액션 | 플랫폼 스코프의 어드민 액션입니다. 로직 번들의 룰 모듈과 카탈로그를 바꾸는 액션이고, 액션 카탈로그의 `domain`이 `"3"`인 항목입니다 | [룰 명세](/policy/rule/reference) |

## 시스템 밖의 배역

시퀀스 다이어그램에 등장하는 Wallet SDK 밖의 주체와 저장소입니다. 배역 리스트가 이 표를 복사합니다.

| 용어 | 무엇인지 | 정의 위치 |
|---|---|---|
| 최종 사용자 | 파트너사 서비스를 쓰는 사람입니다. Wallet SDK 안에서는 Account가 대리합니다 | [계정 계층](/accounts-wallets/accounts) |
| 상대 거래소(VASP) | 최종 사용자가 자산을 보내거나 받는 상대편 가상자산사업자입니다 | [입금](/fund-flows/deposit) |
| 뒷단 플랫폼 | 키 보관·서명과 온체인 관측을 맡는 외부 지갑 인프라입니다. Wallet SDK가 그 위에 구축됩니다 | [시작하기](/start) |
| 온체인 | 블록체인 네트워크 위에서 일어나는 전송과 상태입니다. 온체인 전송은 되돌릴 수 없습니다 | [입금](/fund-flows/deposit) |
| 지갑 원장 | Wallet SDK가 계정·지갑·이동 기록을 저장하는 자기 DB입니다. 파트너사 원장과는 다릅니다 | [도메인 모델](/accounts-wallets/domain-model) |
| 트래블룰 게이트웨이 | 트래블룰 정보를 상대 거래소와 교환하는 중계 시스템입니다 | [입금](/fund-flows/deposit) |
| 이벤트 스트림 | 정책 엔진이 판단 완료·거부 결과를 내보내고 Wallet 서버가 구독하는 비동기 채널입니다 | [서명 게이트](/policy/signing-gate) |
| 인가 저장소 | 발급된 단회성 인가를 보관하고 소비를 기록하는 저장소입니다 | [서명 게이트](/policy/signing-gate) |
| 승인 게이팅 | 어드민 액션이 승인자의 확인을 거쳐야 실행되는 통제입니다 | [승인 게이트](/policy/sequences/approval-gate) |
| 활성 revision | 활성 포인터가 가리키는 번들 개정판입니다. 지금 서빙되는 것입니다 | 설계 기록(내부) |

## 제품의 말과 도메인의 말

제품에서 쓰는 말을 도메인에서 그대로 쓰지 않습니다. 같은 대상을 [홈](/)과 [계정과
지갑](/accounts-wallets)이 다른 말로 부릅니다. 앞은 Wallet SDK가 시장에서 무엇을 대상으로 하는지를
말하고, 뒤는 시스템이 무엇을 강제하는지를 말하기 때문입니다.

### 집금 지갑

집금 지갑은 제품에서 쓰는 말입니다. [홈](/)이 "규제 준수형 집금 지갑"을 포지셔닝 어휘로 씁니다.
개별 지갑(segregated wallet)·내장형 지갑(embedded wallet)과 대비되는 시장 범주입니다. Wallet
SDK가 어느 쪽을 대상으로 하는지가 그 대비에서 나옵니다.

도메인에서는 쓰지 않습니다. 도메인 이름은 `WorkspaceVault`·`WorkspaceWallet`과
`AccountVault`·`AccountWallet`이고, `Omnibus Wallet`·`Deposit Wallet`은 쓰지 않습니다.

가르는 근거는 `D43`입니다. 지갑의 용도를 시스템이 정의하지 않기로 정했습니다. 고객이 태그로
정하고 앱은 그 태그를 해석하지 않습니다. 용도를 이름에 박으면 그 결정이 그 자리에서 깨집니다.
집금이 아닌 용도로 쓰는 vault를 `Omnibus Wallet`이라 부를 수 없기 때문입니다.

**그래서 둘이 부딪히지 않습니다.** 제품의 "집금 지갑"은 파트너사 대다수가 그렇게 쓴다는
시장 사실입니다. 도메인이 그 말을 쓰지 않는 것은 시스템이 그 용도를 강제하지 않는다는 설계 사실입니다.

### 주소와 발급 단위

주소는 발급 단위가 아니라 속성입니다. 제품에서는 주소를 발급 단위로 말합니다. [홈](/)이
"사용자별 입금 주소를 발급한다"고 씁니다. 파트너사가 사는 것이 그 주소이기 때문입니다.

**도메인에서 발급 단위는 `AccountWallet`이고 주소는 거기 붙는 값입니다.** 주소가 바뀌어도 그
행은 남고, 그래서 재발급이 사용자와의 연결을 끊지 않습니다. 주소를 발급 단위로 두면 이 성질을
말할 자리가 없습니다.

## 설계 문서와의 어휘 대조

설계 문서와 이 사이트는 어휘가 갈립니다. 읽는 사람이 다르기 때문입니다. 저장소의 설계 문서는
내부 컴포넌트 이름을 그대로 쓰고, 이 사이트는 대외 어휘로 바꿉니다.

| 설계 문서 | 이 사이트 |
|---|---|
| Sweep | 집금 |
| 제휴사 | 파트너사 |
| custody provider | 뒷단 플랫폼 |
| Admin User | 운영자 |
| 회사외부지갑 | 회사 외부 지갑 |
| 이동 type | 이동 종류 |
| WalletAccount | Account |
| WorkspaceVaultTransfer | Vault 이체 |
| 결정 로그 | 결정 기록 |

**흐름 자체는 바꾸지 않습니다.** 이름만 갈아 끼우고 판정·순서·조건은 설계 문서 그대로 옮깁니다.

## 이름공간과 표기 규칙

이름공간은 둘이고 경계에서 이름이 바뀝니다. API 표면은 camelCase를 쓰고, 엔진 내부 정규 표현의
경로는 snake_case를 씁니다. 두 이름공간의 매핑은 케이스 변환 규칙이 아니라 연산별 명시 선언이고,
정규화기가 그것을 소유합니다(`D-52`).

enum 값의 기준 문서는 TypeSpec입니다. 문서에는 값 목록을 복사하지 않고 원칙만 둡니다. 값 자체는
[API 레퍼런스](/reference)에 있습니다.

판단 입력의 최상위는 룰이 참조하는 값과 `_engine` 예약 키로 나뉩니다(`D-71`). `_engine`은
커널 전용이라 룰이 참조할 수 없고, 카탈로그 필드와 PIP 소스명은 `_`로 시작할 수 없습니다.
컴파일이 이것을 검사합니다.

표시명과 안정 식별자를 구분합니다. 사람이 읽는 이름을 시스템의 신뢰 근거로 올리지 않고, 인증된
caller 신원과 매핑되는 안정 식별자를 씁니다.

식별자는 경계에서 불투명 문자열입니다(`D-105`). 접두사가 붙어 있어도 소비자는 그 포맷에
의존하지 않습니다.

**룰 식별자는 불변이고 은퇴한 것도 재사용하지 않습니다.** 재사용하면 과거 결정 기록이 어느 룰을
가리키는지 판정할 수 없게 됩니다.
