번들 발행

번들 발행(스테이징 + 검증). 활성화하지 않는다.

승인 레코드 실재·정족수 충족·대상 바이트 결속을 전부 발행 이전에 확인한다.

Errors:

  • 400 INVALID_REQUEST: 바디가 없거나 필수 필드가 비었거나 approvalRef가 레코드 형태가 아니다
  • 401 AUTHENTICATION_FAILED: 어드민 세션이 확정되지 않았다
  • 403 PUBLICATION_FORBIDDEN: 발행 권한 role의 platform 부여가 없다
  • 404 PUBLICATION_APPROVAL_UNKNOWN: 발행 승인 레코드가 없다 (자격 밖 참조 포함)
  • 404 DRAFT_REVISION_UNKNOWN: 그런 revision이 없다
  • 409 PUBLICATION_QUORUM_NOT_MET: 정족수가 채워지지 않았다
  • 409 PUBLICATION_PAYLOAD_NOT_APPROVED: 승인된 대상과 다르다
  • 409 PUBLICATION_APPROVAL_ALREADY_USED: 이미 발행에 쓰인 승인 참조다
  • 409 DRAFT_DISCARDED: 폐기된 draft다
  • 422 DRAFT_REVISION_NOT_VALIDATED: 검증을 통과한 revision이 아니다
  • 422 PUBLICATION_COMPILE_CHECK_FAILED: 스냅샷이 컴파일 검사를 통과하지 못했다
POST/policy-bundles/publications

Authorization

AuthorizationBearer token · headerrequired
or
policy_admin_sessionAPI key · cookierequired

Request body

requiredapplication/json
bundleNamestringrequired
draftRevisionIdstringrequired
발행할 저작 revision(TSID prefix dfr-). **바이트의 출처다** — 서버가 이 칸의 저작 세트를 재컴파일해 번들을 만든다. 승인이 이미 이 값을 결속하고 있으므로 중복처럼 보이지만 중복이 아니라 방어다: 발행자가 자기가 무엇을 발행한다고 믿는지를 서버가 그 결속과 대조한다. 어긋나면 409 PUBLICATION_PAYLOAD_NOT_APPROVED다.
approvalRefstringrequired
발행 승인 레코드 식별자(TSID prefix pba-). **자기 주장 값이 아니다** — 레코드 실재와 정족수 충족을 서버가 확인하고, 이미 발행에 쓰인 레코드는 재사용할 수 없다.

codePolicyErrorCoderequired
policy 표면이 내는 `error.code`의 전량. 표면 enum의 합집합에 프레임워크 코드를 더한 것이고, 이 union이 `PolicyApiErrorResponse`의 `code` 타입이다. **wallet 도메인 `ErrorCode`(루트 common.tsp)와 섞이지 않는 것이 계약이다** — 두 값 집합은 겹치는 것이 `INTERNAL_ERROR` 하나뿐이라, 한 봉투로 묶으면 레퍼런스를 읽는 소비자가 policy 응답에서 결코 나오지 않는 코드 마흔여덟 개를 분기 대상으로 받는다. 새 표면 enum을 만들면 여기에 더한다. 더하지 않으면 그 코드는 응답 타입 어디에도 연결되지 않아 생성 스키마에 나타나지 않는다.
