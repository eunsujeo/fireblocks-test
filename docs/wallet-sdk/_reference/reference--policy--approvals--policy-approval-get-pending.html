승인 대기 목록 조회

승인 가능 role 기준 대기 목록.

양쪽 문에서 열린다 — /approvals와 /platform/approvals가 같은 오퍼레이션이고 계정의 소속이 어느 경로를 지날 수 있는지 정한다(policy-api.tsp 문 표).

빈 페이지가 끝을 뜻하지 않는다. 자격 판정이 SQL 술어로 좁혀지지 않아 스캔이 상한만 지고 필터가 뒤에서 도므로, 자격 밖 항목만 담긴 페이지는 비어 나오면서 커서가 다음을 가리킨다. 끝 신호는 cursor가 null인 것 하나다.

Errors:

  • 400 INVALID_REQUEST: 커서가 형태 밖이다 (limit은 서버 상한으로 접힌다)
  • 401 AUTHENTICATION_FAILED: 어드민 세션이 확정되지 않았다

요청자. 본인 승인 불허 판정의 기준. **어드민 액션(어드민 세션이 낸 요청)일 때만 있다** — 서명 연산의 principal은 서비스이고 (D-103), 서비스 신원은 승인 주체 타입이 될 수 없다(D-104 sealed 계층). 없으면 본인 승인 불허가 무조건 성립하는 것이지 검사가 생략되는 것이 아니다.
challengeIdstringrequired
이 요청에 표를 던질 때 제출해야 하는 챌린지 id(§7). 난수가 아니라 `policyRequestId` + canonical intent 전문 해시(JCS+SHA-256 — D-91)에서 유도되므로 서버가 재계산해 대조한다 — 다른 요청에 받은 값은 여기서 어긋난다(dynamic linking). 비밀이 아니라 **바인딩**이다. 세션 탈취를 막는 것은 이 값이 아니라 함께 제출하는 `challengeResponse`(건별 2FA)다.

policy 표면이 내는 `error.code`의 전량. 표면 enum의 합집합에 프레임워크 코드를 더한 것이고, 이 union이 `PolicyApiErrorResponse`의 `code` 타입이다. **wallet 도메인 `ErrorCode`(루트 common.tsp)와 섞이지 않는 것이 계약이다** — 두 값 집합은 겹치는 것이 `INTERNAL_ERROR` 하나뿐이라, 한 봉투로 묶으면 레퍼런스를 읽는 소비자가 policy 응답에서 결코 나오지 않는 코드 마흔여덟 개를 분기 대상으로 받는다. 새 표면 enum을 만들면 여기에 더한다. 더하지 않으면 그 코드는 응답 타입 어디에도 연결되지 않아 생성 스키마에 나타나지 않는다.
