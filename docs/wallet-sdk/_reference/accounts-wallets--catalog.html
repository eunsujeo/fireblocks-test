카탈로그

Network · Token — 무엇을 담을 수 있는지

카탈로그는 지갑이 무엇을 담을 수 있는지 정하는 기준입니다. Network가 블록체인 네트워크이고 Token이 그 위의 자산이며, Wallet은 Token 하나를 담습니다. 등록 주체와 가시성 규칙은 Network와 Token에서 다릅니다.

Network

블록체인 네트워크입니다. 각 네트워크는 서로 완전히 독립적으로 동작합니다. 잔액도 주소도 트랜잭션도 네트워크를 넘지 않습니다.

플랫폼이 관리합니다. 워크스페이스 운영자가 등록하지 않고, 어느 네트워크를 쓸 수 있는지는 플랫폼 수준에서 정해집니다. 워크스페이스가 하는 일은 그 네트워크 위에 토큰을 등록하는 것입니다.

네트워크 계열에 따라 주소 체계가 갈립니다. 지금 계약에 있는 값은 EVM 하나이고 Solana가 예약돼 있습니다. 카탈로그는 이 값을 protocol로 냅니다.

Token

Wallet이 담는 단위입니다. Network 위의 자산 하나를 나타냅니다. 같은 자산이라도 네트워크가 다르면 다른 Token입니다.

예를 들어 다음은 서로 다른 Token 넷입니다.

  • BASE 네트워크의 USDC
  • Ethereum 네트워크의 USDC
  • Solana 네트워크의 KRWK
  • Solana 네트워크의 Wrapped Ether

워크스페이스 운영자가 등록합니다. 등록해야 그 토큰의 지갑을 만들고 출금할 수 있습니다.

유일성은 (workspace, network, 컨트랙트 주소) 조합에서 성립합니다. networkId는 스코프 키가 아니라 조회 조건입니다.

symbol은 키가 아닙니다. 같은 체인에 동명 토큰이 등록되는 것이 정당하기 때문입니다. 자산 식별자와 소수점 자릿수는 뒷단 플랫폼이 정하고, symbol·이름·아이콘은 요청이 정합니다.

표면별 가시성

계약 소유자와 인증 방식이 하나로 정해지는 API 경로 묶음인 표면(자세히)마다 가시성이 다릅니다.

운영자 조회는 상태로 거르지 않습니다. 거르면 비활성 토큰을 되돌릴 방법이 사라집니다.

파트너사 조회는 토큰과 소속 Network가 모두 활성인 것만 냅니다. 파트너 계약에 상태 필드가 없어 노출된다는 사실 자체가 “쓸 수 있다”는 신호이고, Network가 비활성이면 그 networkId를 파트너가 해석할 수 없기 때문입니다.
