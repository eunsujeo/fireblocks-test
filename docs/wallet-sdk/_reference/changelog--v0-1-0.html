참고 문서

v0.1.0

계약 변경

  • API 레퍼런스 주소가 바뀝니다. OpenAPI 태그를 영문 전용으로 바꾸고 한글은 태그 설명으로 옮겼습니다. 예전 주소를 북마크해 두셨다면 다시 잡아 주십시오 — 엔드포인트 경로와 요청·응답 스키마는 그대로입니다.
  • 낼 수 없는 에러 코드를 지웠습니다. 집금 생성(POST /api/v1/sweeps) 문서의 IDEMPOTENCY_KEY_TOO_LONG을 걷었습니다. 서버가 그 코드를 내지 않으므로 그것으로 분기하는 코드가 있다면 도달하지 않는 분기입니다.
  • 정책의 자산 좌표가 토큰 식별자가 됐습니다. 판단 요청의 정규화 결과에서 asset 객체가 token으로 바뀌었습니다. 요청 스키마는 그대로지만 룰에서 asset.id를 참조했다면 token.id로 고쳐야 합니다. 대신 체인 무관 그룹 룰(“전 체인 USDC 하루 한도”)은 지금 표현할 수 없어 체인마다 따로 걸어야 합니다.
  • 회수한 주소를 다시 등재하면 식별자가 새로 붙습니다. 동작이 바뀐 것이 아니라 계약으로 적혀 있지 않던 것인데, 옛 식별자를 보관하는 연동이 깨지므로 계약 변경으로 다룹니다. 닫힌 항목의 식별자는 다시 쓰이지 않습니다. 출금 요청은 목적지 주소로 매칭하므로 영향받지 않습니다. → 주소록
  • vault 사이 이체의 잔액 부족은 요청 응답이 아니라 이체 상태로 드러납니다. 접수할 때 금액을 예약하고 결과로 확정하거나 풉니다. 온체인 잔액은 요청 시점에 조회하지 않으므로 접수됐다고 이체가 나간 것이 아닙니다 — 상태를 끝까지 따라가셔야 합니다. → 자금 동결
  • 토큰 카탈로그 응답에서 assetId가 빠졌습니다. 내부 표면 GET /internal/v1/token-catalog이고 파트너사 연동에는 영향이 없습니다. 체인 무관 자산 키를 채울 기준이 없어 비어 있던 필드입니다.

문서

  • 이 사이트가 서술 문서의 기준이 됐습니다. 어느 서술이 맞는지 갈릴 때는 여기가 우선합니다. API 계약의 기준 문서는 그대로 TypeSpec입니다 — 엔드포인트·스키마·에러 코드는 이 승격의 대상이 아니었습니다.
  • 제품·설계 기록 두 섹션이 생겼습니다. 무엇을 대상으로 하는 제품이고 어디까지 제공하는지, 그리고 무엇을 왜 그렇게 정했는지의 이력입니다. 설계 기록은 범위를 줄이지 않고 벤더 실명·내부 컴포넌트 이름·폐기된 결정까지 그대로 싣습니다.
  • 첫 요청과 규제 대응이 생겼습니다. 계정을 만들고 입금 주소를 받기까지를 순서대로 밟습니다. 종전에는 표면 목록만 있고 처음부터 끝까지 이어 가는 길이 없었습니다.
  • 원본 22편을 동결했습니다. docs/wallet-system/ 아래 원본은 이력으로 남고 거기서 한 수정은 이 사이트에 반영되지 않습니다. 어느 절이 어디로 갔는지는 이동 기록에 파일 단위로 있습니다.
  • 제품 이름을 Wallet SDK로 통일하고 본문 폰트를 SUIT로 바꿨습니다. 코드 블록의 서체는 그대로입니다.
