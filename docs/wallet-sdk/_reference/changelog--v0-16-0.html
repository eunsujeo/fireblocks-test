참고 문서

v0.16.0

계약 변경

  • Policy API의 오류 응답이 policy 코드 집합으로 바뀝니다. 그동안 레퍼런스가 Wallet 도메인 오류 코드 48개를 policy 응답의 error.code로 광고했지만, 서버가 실제로 내는 것은 policy 표면의 코드입니다. 이제 PolicyApiErrorResponse가 표면별 enum과 프레임워크 폴백 코드의 합집합을 답니다. Wallet 코드로 분기하던 클라이언트는 그 분기가 닿지 않던 것이니 지워도 됩니다. → 내부 API
  • 미등재였던 오류 코드가 전부 레퍼런스에 오릅니다. 승인·초안·발행 표면의 코드와 접수 거부 DRAINING·INTAKE_SATURATED(503), 역할 거부 FORBIDDEN_ROLE(403)입니다. 서버 동작은 그대로입니다.
  • 어드민 표면의 문 접두가 계약에 드러납니다. platform 전용 표면(부트스트랩·번들 활성화·워크스페이스 등록)은 경로가 /platform으로 시작합니다. 양쪽 문에서 열리는 표면은 접두 없는 경로를 유지하고 /platform 사본이 함께 열립니다. → 내부 API
  • 워크스페이스 등록·매니저 관리 표면 7개와 번들 서빙 표면 2개가 레퍼런스에 오릅니다. 등록 표면은 platform 어드민 세션과 건별 스텝업을 요구합니다. → 인계 계약
  • 어드민 세션을 쿠키로도 받고 로그아웃 표면이 생깁니다. POST /auth/2fa가 policy_admin_session 쿠키를 내리고, POST /auth/logout이 그것을 지웁니다. 요청 하나에 자격 출처는 하나입니다.
  • 응답 필드가 셋 늘고 하나가 nullable이 됩니다. 세션 신원에 homeScope·permissions, 초안 검증에 warnings가 실립니다. 승인 대기 항목의 expiresAt은 대기 구간에 null입니다.

문서

  • 정책 엔진 페이지 23편을 코드와 대조해 고쳤습니다. 인계 계약의 등록 표면 자격이 반대로 적혀 있던 것, 인가 TTL 기본값(10분 → 20분), 룰 구조의 예시 룰, 저장·정규화·PIP 도착 검사의 서술이 대상입니다. 설계가 코드보다 앞선 자리(승인 게이트·obligation 이행)는 설계를 남기고 구현 상태를 적었습니다. → 승인 게이트
  • 워크스페이스 온보딩 결정이 D-227로 올랐습니다. D-205는 부분, D-208은 폐기로 내렸습니다. → 결정 색인
  • 구현 대기 표가 정책 표면을 제대로 셉니다. 파서가 여러 줄 어노테이션과 상수 경로를 못 읽어 Policy API 33개 중 27개를 「계약만」으로 세던 것을 고쳤습니다. → 구현 대기
  • 용어집에 소속 스코프·문·릴레이·introspection·스텝업을 올렸습니다. → 용어
