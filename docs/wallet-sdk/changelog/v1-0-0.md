### 문서

- **탭을 파트너사가 붙이는 기능 영역으로 다시 잘랐습니다.** 시작하기 · 계정과 지갑 · 자금 이동 · 정책 ·
  API 레퍼런스 · 변경 이력 여섯입니다. 「핵심 개념」 탭은 「계정과 지갑」이 되었고, 시작하기의 제공
  범위·에코시스템은 [홈](/)의 두 절로 들어갔습니다. 내부용 서술은 설계 기록 탭 하나로 모였고 그 탭은
  private 본에만 실립니다.
- **URL 이 전부 바뀌었고 리다이렉트는 두지 않습니다.** 옛 주소는 더 이상 응답하지 않습니다. 아래 대응표로
  새 주소를 잡고, 옛 서술이 필요하면 헤더의 버전 스위처에서 v0 를 고릅니다. 이 표 밖의 라우트(자금 이동
  각론·정책 룰·평가·유즈케이스·API 레퍼런스)는 그대로입니다.
- **모든 서술 페이지를 설명형 문체로 다시 쓰고 tsp·DDL·코드와 대조해 정정했습니다.** 정정 내역과
  대조에서 드러난 구현 결함은 이 항목의 아래 절과 설계 기록의 드리프트에 있습니다.
- **Tenant 의 정의를 정정했습니다.** 「그 회사가 운영하는 서비스 하나」가 아니라 **Workspace 아래에서
  Account 를 묶는 계정 체계 하나**입니다. 카카오페이의 유저 월렛과 비즈 월렛이 계정 체계 둘입니다.
  [계정 계층](/accounts-wallets/accounts), [용어](/start/terminology), [표면과 인증](/start/authentication),
  [첫 요청](/start/first-request) 네 페이지가 v0.5.0 부터 옛 정의를 적고 있었습니다.
- **계정과 지갑 개요는 두 계층이 왜 있고 무슨 역할인지만 서술합니다.** 정의와 API 계약은 계층별 페이지가
  갖습니다. 개요와 하위 페이지가 같은 정의를 각자 적던 자리를 정리했습니다. 홈의 「먼저 알아 둘 것」과
  시작하기 개요도 소유 페이지 문장을 되풀이하지 않게 줄였습니다.
- **함축 표현을 쓰지 않는 규칙을 문체 규칙에 넣고 58장을 다시 훑었습니다.** 「자산의 좌표」「격리 축」처럼
  낱말 하나에 문장을 접어 넣은 말, 「담습니다」「걸립니다」「닫힙니다」 같은 은유 동사, 풀지 않은 한자어를
  뜻 그대로 쓴 말로 바꿨습니다. 전수 조사에서 446건이 나왔고 그중 뜻이 하나인 낱말은 검사기가 잡습니다.
  용어 페이지에 정족수, 값 이동, 저작 세트, 채점을 등재했습니다.
- **사이드바를 절로 묶었습니다.** 자금 이동 탭은 이동 종류 아래에 「이동」(입금 · 집금 · 출금 · Vault 이체)과
  「제어와 통지」(자금 동결 · 웹훅 · 주소록) 두 절로 나뉩니다. 정책 탭의 룰·평가와 설계 기록의 그룹 셋은
  접이식에서 펼친 절로 바뀌어 열지 않고도 안이 보입니다. 주소는 하나도 바뀌지 않았습니다.
- **드리프트 페이지를 색인과 상세 둘로 나눴습니다.** `/internal/status/drift` 는 항목 표가 되고 상세는
  `/internal/status/drift-wallet` 과 `/internal/status/drift-policy` 에 있습니다. 셋 다 private 본에만 있습니다.
- **문서 버전이 v1 입니다.** URL 계약이 통째로 바뀌어 major 를 올렸습니다. 문서 버전은 구현 성숙도가
  아닙니다 — 계약 130개 중 34개가 아직 동작하지 않고, 어디까지 동작하는지는 설계 기록의 구현 대기와
  알려진 제약이 답합니다.

### private 로 이동해 protected 본에서 사라진 라우트

설계 기록 탭(`/internal/*`)은 private 본에만 있습니다. 아래 아홉은 옛 주소가 protected 본에 있었거나
protected 본에서 읽을 수 있던 페이지입니다. 그중 앞의 넷은 이전부터 private 이었고, 뒤의 다섯은 이번에
내부용으로 판정해 옮겼습니다 — 정책 엔진을 만드는 쪽의 서술이라 파트너사 통합에는 필요하지 않고,
그 파이프라인은 [구조](/policy/architecture)와 [룰 저작과 발행](/policy/workflow)이 한 문단으로
서술합니다.

| 옛 | 새 (private) |
|---|---|
| `/concepts/identifiers` | `/internal/identifiers` |
| `/start/known-limits` | `/internal/known-limits` |
| `/policy/ops/internal-api` | `/internal/policy-internals/internal-api` |
| `/policy/ops/handoff` | `/internal/policy-internals/handoff` |
| `/policy/authoring/sources` | `/internal/policy-internals/sources` |
| `/policy/authoring/artifacts` | `/internal/policy-internals/artifacts` |
| `/policy/authoring/compilation` | `/internal/policy-internals/compilation` |
| `/policy/authoring/bundles` | `/internal/policy-internals/bundles` |
| `/policy/runtime/persistence` | `/internal/policy-internals/persistence` |

설계 기록 안에서도 넷이 움직였습니다 — `/internal/{drift,conflicts,roadmap,implementation-review}` 와
생성물 `/internal/pending` 은 `/internal/status/` 아래로 갔습니다.

### v0 스냅샷

재편 직전의 서술 88장이 `/v0/` 아래에 그대로 있습니다. 헤더의 버전 스위처에서 v0 를 고르면 옛 주소
체계로 읽을 수 있습니다. API 레퍼런스는 스냅샷에 들어가지 않아 최신 버전만 있고, 스냅샷 안의
레퍼런스 링크는 최신 레퍼런스로 나갑니다. 스냅샷은 한동안 유지하다 후속 릴리즈에서 지웁니다.

### 옛 주소는 더 이상 응답하지 않습니다

이전 발행분의 변경 이력 안에 옛 라우트로 가는 링크가 24건 있습니다. 발행된 기록은 소급해 고치지 않으므로
그 링크는 404 로 남습니다. 필요한 페이지는 위 대응표로 찾습니다.
