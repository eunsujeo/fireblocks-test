정책 평가와 서명

정책 엔진이 요청을 평가해 일회용 인가를 발급합니다. 서명 직전에는 실제 트랜잭션이 인가 내용과 일치하는지 검사합니다.

평가와 서명 검증

설계 흐름과 현재 연결 상태

아래는 정책 연동 설계입니다. v1.1.0 문서는 Wallet 서버와 실 정책 서버가 아직 연결되지 않았고 현재 동기 자동 승인한다고 명시합니다. 이 다이어그램을 현재 배포에서 검증된 처리로 보지 않습니다.

참고: 정책 결과와 현재 구현 ↗

  1. 요청 접수와 사실 수집

    Wallet 서버가 정책 엔진에 판단을 요청하면 202와 판단 식별자를 받습니다. 엔진은 요청을 정규화하고 필요한 사실을 모읍니다. PIP는 이때 주소 소유 같은 판단 자료를 읽는 수집 경로입니다.

  2. 판단과 추가 조건

    평가기(PDP)가 입력에 룰을 적용합니다. 자료·승인 조건에 따라 재평가하는 설계입니다. 현재 서명 연산에는 obligation 루프가 없어 정족수를 요구할 수 없고, 자산별 금액 상한도 token_catalog 수집이 없어 작성할 수 없다고 설명합니다.

  3. 일회용 인가 발급

    허용된 판단은 유효 시간이 있는 signingAuthorizationId를 발급합니다. Wallet 서버는 결과 이벤트를 받아 인프라에 제출할 때 이 인가 ID를 외부 참조 ID로 연결합니다.

  4. 서명 직전 대조와 소비

    Co-Signer가 보낸 서명 대상을 인가 내용과 대조합니다. 인가가 유효하고 내용이 맞으면 원자적으로 한 번 소비합니다. 이 단계는 외부 심사 시스템을 호출하지 않습니다.

참고: 서명 게이트 ↗ · 평가의 순간 ↗ · PIP ↗

요청 접수와 결과 통지

경계응답·판단의미
파트너 → Wallet API이동 요청 생성의 201업무 엔티티 생성. 온체인 완료 아님
Wallet → 정책 엔진판단 접수 202비동기 평가 시작. 파트너 API의 응답 코드와 다름
정책 엔진 → Wallet허용·거부 결과 이벤트허용 시 인가를 근거로 후속 제출
서명 인프라 → 정책 콜백서명 대조 승인·거부이미 허용된 요청과 실제 서명할 내용의 일치 확인
SDK → 파트너업무별 FINALIZED 또는 FAILED 웹훅파트너가 자기 업무 식별자로 결과 반영

정책 엔진의 중복 판단 요청은 409 규칙을 따릅니다. 파트너 API의 중복 생성 처리는 각 업무의 referenceId와 Idempotency-Key 계약을 확인해야 합니다.

참고: 서명 게이트 ↗ · 웹훅(Webhook) ↗ · 첫 요청 ↗

인가 유효 시간

서명 인가의 TTL은 기본·하한 20분, 상한 60분입니다. 정책을 새로 배포해도 이미 발급된 인가는 TTL까지 유효합니다.

서명 콜백은 외부 데이터를 다시 읽지 않습니다. 따라서 주소를 긴급 차단하거나 정책을 바꿨을 때 기존 인가를 어떻게 취소·차단할지는 별도로 확인해야 합니다. 일회용 인가 소비가 파트너 원장 반영까지 한 번만 일어나게 해주는 것은 아닙니다.

참고: 서명 게이트 ↗ · 결정과 결합 ↗

운영자 승인

경로문서가 설명하는 상태
자금 이동의 서명 게이트정책 판단과 실제 서명 대조를 연결하는 2단계
일반 admin_action 승인 게이트접수 표면에서 403으로 거부. 승인 뒤 권한 적용·발행 경로도 아직 없음
현재 룰 변경 승인초안 revision의 내용 해시에 표를 결속하는 별도 maker-checker. 발행과 활성화는 각각 호출
현재 역할 부여초대 표면에서 직접 인가. 제안자·승인자를 나누는 단계는 없음
admin_action 미지원

통합 admin_action 승인 경로는 아직 동작하지 않습니다. 운영자 승인이 필요한 액션은 현재 제공되는 개별 경로와 지원 범위를 확인해야 합니다.

참고: 승인 게이트 ↗

Wallet Admin 승인 API의 현재 한계

Approvals API 세 개는 고정 응답을 냅니다. 승인 게이팅을 거치는 엔드포인트도 현재 APPROVED·DENIED만 내며 quorum은 null입니다. 반환·해제의 정족수 승인이 동작한다고 전제하지 않습니다. Policy API의 통합 admin_action 미지원과 구분해 확인합니다.

정책 작성과 결과 확인

서명 게이트 → 룰 쓰기 → 예시 정책 → 룰 저작과 발행 → 결과 읽기 순서로 읽습니다. 엔진 내부 동작은 별도 참고 문서에서 확인합니다.

항목확인할 내용
룰 필드요청 필드는 scope·when에서, 평가 중 PIP가 수집하는 필드는 when에서 사용합니다. 참조 가능 필드 표는 원문의 생성된 카탈로그를 확인합니다.
시드 집금 정책EVM·서비스 주체·deposit → custody 내부 이동을 허용합니다. PIP 조건은 없습니다. 이 종류 구분만으로 핫·콜드·고객·회사 용도 태그 통제가 완성되지는 않습니다.
승인·발행승인은 검증된 revision의 내용 해시에 묶입니다. 내용을 고치면 다시 검증·승인해야 하며 발행과 활성화는 별도 액션입니다.
현재 제약서명 연산 정족수 루프와 자산별 금액 상한 조건은 현재 사용할 수 없다고 명시합니다. resource_limit_per_tx는 건당 수수료 상한이며 송금액 상한과 다릅니다.
