정책 평가와 서명

정책 엔진이 요청을 평가해 일회용 인가를 발급합니다. 서명 직전에는 실제 트랜잭션이 인가 내용과 일치하는지 검사합니다.

평가와 서명 검증

  1. 요청 접수와 사실 수집

    Wallet 서버가 정책 엔진에 판단을 요청하면 202와 판단 식별자를 받습니다. 엔진은 요청을 정규화하고 필요한 사실을 모읍니다. PIP는 이때 주소 소유 같은 판단 자료를 읽는 수집 경로입니다.

  2. 판단과 추가 조건

    평가기(PDP)가 입력에 룰을 적용합니다. 자료가 더 필요하면 수집하고, 2FA·정족수 등의 obligation이 붙으면 이행 후 재평가하는 구조입니다. 도표에 등장하는 모든 수집 연동이 구현되었다는 뜻은 아닙니다.

  3. 일회용 인가 발급

    허용된 판단은 유효 시간이 있는 signingAuthorizationId를 발급합니다. Wallet 서버는 결과 이벤트를 받아 인프라에 제출할 때 이 인가 ID를 외부 참조 ID로 연결합니다.

  4. 서명 직전 대조와 소비

    Co-Signer가 보낸 서명 대상을 인가 내용과 대조합니다. 인가가 유효하고 내용이 맞으면 원자적으로 한 번 소비합니다. 이 단계는 외부 심사 시스템을 호출하지 않습니다.

요청 접수와 결과 통지

경계응답·판단의미
파트너 → Wallet API이동 요청 생성의 201업무 엔티티 생성. 온체인 완료 아님
Wallet → 정책 엔진판단 접수 202비동기 평가 시작. 파트너 API의 응답 코드와 다름
정책 엔진 → Wallet허용·거부 결과 이벤트허용 시 인가를 근거로 후속 제출
서명 인프라 → 정책 콜백서명 대조 승인·거부이미 허용된 요청과 실제 서명할 내용의 일치 확인
SDK → 파트너업무별 FINALIZED 또는 FAILED 웹훅파트너가 자기 업무 식별자로 결과 반영

정책 엔진의 중복 판단 요청은 409 규칙을 따릅니다. 파트너 API의 중복 생성 처리는 각 업무의 referenceId와 Idempotency-Key 계약을 확인해야 합니다.

인가 유효 시간

서명 인가의 TTL은 기본·하한 20분, 상한 60분입니다. 정책을 새로 배포해도 이미 발급된 인가는 TTL까지 유효합니다.

서명 콜백은 외부 데이터를 다시 읽지 않습니다. 따라서 주소를 긴급 차단하거나 정책을 바꿨을 때 기존 인가를 어떻게 취소·차단할지는 별도로 확인해야 합니다. 일회용 인가 소비가 파트너 원장 반영까지 한 번만 일어나게 해주는 것은 아닙니다.

참고: 서명 게이트 ↗ · 결정과 결합 ↗
