웹훅과 장애 복구

웹훅을 받아 업무 상태와 원장에 반영합니다. 중복 통지, 순서가 바뀐 통지, 응답을 받지 못한 요청을 처리하는 방법을 설명합니다.

이 페이지 목차
이벤트 목록중복 수신과 순서 역전업무별 재조회 방법복구 절차운영 전 확인 사항

이벤트 목록

업무진행 알림완료·실패 알림
입금DEPOSIT_DETECTEDDEPOSIT_FINALIZED / DEPOSIT_FAILED
입금 정보 갱신DEPOSIT_UPDATED · 현재 미구현확정 뒤 보강 정보를 알리는 설계이며 새 입금을 뜻하지 않음
SweepSWEEP_INITIATEDSWEEP_FINALIZED / SWEEP_FAILED
고객·자체 출금 등 출금WITHDRAWAL_INITIATEDWITHDRAWAL_FINALIZED / WITHDRAWAL_FAILED
VaultTransfer별도 INITIATED 없음VAULT_TRANSFER_FINALIZED / VAULT_TRANSFER_FAILED

입금 FINALIZED는 온체인 확정입니다. 내부 동결이 풀렸다는 의미가 아닙니다. 이동 요청의 생성 응답과 시작 알림도 온체인 완료가 아닙니다.

참고: 웹훅(Webhook) ↗ · 입금 (Deposit) ↗

중복 수신과 순서 역전

입금 웹훅의 correlationKey 형식은 {depositId}:{eventType}입니다. 입금 ID만으로 중복 제거하면 같은 입금의 감지와 확정 중 하나를 버릴 수 있습니다. 계획된 UPDATED 이벤트에는 seq가 추가됩니다. 다른 이동 이벤트의 중복 키 형식은 해당 계약을 확인해야 합니다.

파트너 수신부 구현 시 권장사항

수신 이벤트 원본과 중복 키를 저장하고, 원장 반영과 처리 완료 표시를 같은 로컬 트랜잭션으로 묶는 것을 권장합니다. 늦게 도착한 진행 이벤트가 완료된 업무를 되돌리지 않도록 상태 전이를 제한합니다. 상태가 충돌하면 최신 값을 조회해 조정합니다.

웹훅은 4xx와 5xx 응답 모두 재시도합니다. 재시도 기간, 재전송·보관 범위, 서명 검증 방식, 이벤트의 순서·버전 규칙은 연동 전에 추가로 확인해야 합니다.

참고: 웹훅(Webhook) ↗

업무별 재조회 방법

작업기존 결과 찾기주의
계정 생성GET /api/v1/accounts?referenceId=…중복 생성은 400. 조회로 accountId 회수
AccountWallet 생성GET /api/v1/accounts/{accountId}/account-walletsIdempotency-Key 미구현. 목록만으로 식별이 안 되면 새 생성 보류
SweepGET /api/v1/sweeps?referenceId=…같은 referenceId로 기존 집금을 복구하는 계약
고객 출금개별 ID 조회 또는 계정 출금 목록referenceId 전용 조회 API 없음
VaultTransferGET /api/v1/workspace-vault-transfers?referenceId=…provider 결과 불명 503도 PENDING일 수 있음

참고: 첫 요청 ↗ · 집금 (Sweep) ↗ · Vault 이체 (Vault Transfer) ↗ · 출금 내역 목록 조회 ↗

복구 절차

  1. 응답을 못 받았을 때

    먼저 기존 업무 ID 또는 referenceId로 조회합니다. 타임아웃만으로 “요청이 실행되지 않았다”고 판단하지 않습니다.

  2. 온체인 처리 중일 때

    최신 업무 상태·txHash를 확인합니다. 별도 새 요청으로 동일 금액을 다시 보내기 전에 이전 제출 결과를 조정합니다.

  3. 실패가 확정됐을 때

    예약 해제와 입금 FROZEN 복귀 등 해당 업무의 복구 상태를 확인합니다. 원래 요청의 재접수와 새로운 업무 요청을 구분하여 이력을 보존합니다.

  4. 완료된 이벤트가 다시 왔을 때

    이미 반영한 원장 처리를 반복하지 않습니다. 이벤트 보관과 원장 반영의 성공 여부를 함께 확인합니다.

참고: Vault 이체 (Vault Transfer) ↗ · 집금 (Sweep) ↗ · 자금 동결 ↗

운영 전 확인 사항

추가로 필요한 운영 계약

확정 후 깊은 reorg의 보정 방식, 웹훅 서명·재전송 계약, 온체인 거래 안의 개별 이동 식별 규칙, 모호한 요청의 조정 기한과 담당 주체를 확인해야 합니다. 현재 입금 조회 OpenAPI에는 트래블룰·KYT 필드가 없습니다. 웹훅에 추가될 이 정보를 조회로도 복구할 수 있는지 확인이 필요합니다.

참고: 입금 (Deposit) ↗ · 웹훅(Webhook) ↗ · 입금 내역 상세 조회 ↗
