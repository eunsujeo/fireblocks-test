Vault 간 이체

같은 Workspace에 속한 Vault 사이에서 자산을 옮깁니다. 요청 시 금액을 예약하고, 온체인 결과에 따라 예약을 확정하거나 해제합니다.

이체 조건

동일 Workspace의 WorkspaceVault 사이에서만 이동합니다. 출발과 목적지는 서로 달라야 하며 둘 다 활성 상태여야 합니다. AccountVault는 어느 쪽에도 쓸 수 없습니다.

내부 이체에는 외부 주소록·트래블룰 단계가 없습니다. 정책 평가와 서명 인가는 필요합니다. 고객 자산과 회사 자산 사이의 이동 허용 여부도 별도로 정해야 합니다.

참고: Vault 이체 (Vault Transfer) ↗

이체 요청

POST요청 예시
POST /api/v1/workspace-vault-transfers
X-API-KEY: <발급받은_API_키>
Idempotency-Key: <요청_식별자>
Content-Type: application/json

{
  "sourceVaultId": "<출발_wv_ID>",
  "destinationVaultId": "<목적지_wv_ID>",
  "tokenId": "<이체_tokenId>",
  "amount": "1.25",
  "referenceId": "vault-transfer-job-0001"
}

referenceId는 Workspace 안에서 이체 업무를 식별합니다. Idempotency-Key는 명세상 필수이지만 이체 안내는 해당 헤더가 아직 동작하지 않는다고 명시합니다. 201 응답의 workspaceVaultTransferId를 저장합니다. 금액은 양수여야 하며 토큰 정밀도를 따라야 합니다.

참고: 워크스페이스 Vault 이체 요청 생성 ↗

잔액 예약과 전송

  1. 입력과 사용 가능 잔액 검사

    동일 Vault, 비활성 Vault, 잘못된 금액을 거부합니다. 문서의 사용 가능 잔액 개념은 온체인 잔액에서 동결 금액과 진행 중 예약 금액을 뺀 값입니다.

  2. 예약과 정책 판단

    VaultTransfer는 잔액을 예약합니다. 정책 거부를 동기 응답으로 반환하는지, 비동기 결과로 통지하는지는 문서 간 설명이 다릅니다.

  3. 서명과 온체인 제출

    인가와 실제 서명 대상을 대조하여 제출합니다. 원장 예약은 실시간 온체인 잔액 조회를 대신하지 않으므로 provider에서 잔액 부족으로 실패할 수 있습니다.

  4. 최종 결과 처리

    성공하면 예약을 소비하고, 확정 실패라면 예약을 해제하는 계약입니다. 결과가 불명확한 상태를 곧바로 실패로 처리하면 안 됩니다.

정책 거부 응답 미확정

VaultTransfer 문서는 정책 거부 시 400 WORKSPACE_VAULT_TRANSFER_POLICY_DENIED를 반환한다고 설명합니다. 공통 서명 게이트는 접수 후 비동기 거부 이벤트를 설명하므로, 실제 호출자가 받을 응답을 구현 담당자와 확정해야 합니다.

참고: Vault 이체 (Vault Transfer) ↗ · 자금 동결 ↗ · 서명 게이트 ↗
