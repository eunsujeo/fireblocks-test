계정과 지갑

계정은 사용자를 식별하고, Vault와 Wallet은 자산을 보관할 지갑을 구성합니다. 고객별 귀속 금액은 파트너 원장에서 관리합니다.

고객 원장

SDK는 주소·지갑과 이동 이벤트를 관리합니다. 집금 후에도 고객별 귀속 금액을 추적하려면 파트너 원장이 필요합니다. 고객 자산과 회사 자산의 구분도 원장과 지갑 배치에 함께 반영해야 합니다.

Vault와 Wallet

객체용도식별과 주소
WorkspaceVault파트너가 자금을 보관하고 출금·이체하는 지갑 그룹API의 출발·목적지에는 wv-… Vault ID 사용
AccountVault고객 측 지갑을 묶는 내부 그룹공개 API로 직접 생성하지 않음. 첫 AccountWallet 생성에 따라 마련됨
AccountWallet고객의 토큰별 입금 지갑aw-… Wallet ID와 accountId를 연결
주소온체인 수신·송신 위치현재 EVM에서는 같은 Vault의 EVM 지갑들이 같은 주소를 공유

현재 EVM 모델에서는 같은 Vault의 토큰별 Wallet이 주소를 공유합니다. 서로 다른 주소가 필요하면 Vault를 분리해야 합니다. 온체인 기록을 저장할 때는 주소만으로 식별하지 않도록 네트워크와 토큰도 함께 보존하는 것을 권장합니다.

중복 처리 방식은 API마다 다릅니다. 계정 생성은 같은 referenceId에 400을 반환하므로 조회로 기존 계정을 찾습니다. 지갑 생성은 Idempotency-Key가 필수지만 중복 방지 처리가 아직 없습니다. OpenAPI의 헤더 설명과 실제 지원 범위를 함께 확인해야 합니다.

Vault 용도와 자산 분리

Vault에 용도 태그를 붙일 수 있지만 SDK가 이를 해석하지는 않습니다. 태그를 정책 입력으로 읽는 PIP도 아직 없습니다. 출금 풀로 표시한 Vault만 목적지로 허용하려면 별도의 통제 방법이 필요합니다.

자산 분리 설계

고객 보관용과 회사 자산용 Vault의 식별 방법, 허용할 이동 조합, 주소 등록·활성화 권한을 정해야 합니다. 이 구분을 SDK가 자동으로 집행하는지는 공개 문서만으로 확인되지 않습니다.
