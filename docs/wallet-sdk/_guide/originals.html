문서 기준

이 가이드는 2026-09-10의 Wallet SDK 공개 문서를 바탕으로 작성했습니다. 공식 문서를 재구성한 자료이며 SDK 소스나 실제 API를 검증한 결과는 아닙니다. 본문의 참고 링크에서 근거를 확인할 수 있습니다.

현재 버전 원문 198개와 상세 API 명세를 보존했습니다. 과거 v0 문서는 제외했으며, 현재 문서에 포함된 변경 이력은 남겼습니다. 원문 상단의 Wallet SDK를 누르면 가이드 첫 화면으로 돌아옵니다.

  • 시작하기 ↗

    첫 요청에서 자금 이동까지, 파트너사 개발자가 읽는 순서

  • 표면과 인증 ↗

    어떤 API를 누가 부르고, 무엇이 인증에서 나오는가

  • 규제 대응 ↗

    접속기록·개인정보·보존·암호키가 어느 페이지에 있는가

  • 첫 요청 ↗

    계정을 만들고 입금 주소를 받기까지

  • 용어 ↗

    어느 말이 무엇을 가리키고 그 정의가 어디 있는지

  • 지갑 계층 ↗

자금 이동 9

  • 자금 이동 ↗

    온보딩에서 주소록까지, 자금이 흐르는 경로

  • 주소록 (Address Book · Whitelist) ↗

    출금 목적지 화이트리스트 — 주소에 근거를 붙이고, 정책이 그 근거를 읽습니다

  • 입금 (Deposit) ↗

    온체인 전송에서 확정 통지까지, 그리고 동결을 풀어도 되는지 판단하는 사전·사후 확인

  • 이동 종류 ↗

    어디서 어디로 갈 수 있는가

  • 자금 동결 ↗

    자동 해제가 없는 이유와 두 해제 경로, 그 아래 깔린 동시성 방어

  • 집금 (Sweep) ↗

    입금 건을 지목해 옮기고, 그 이동이 해제를 겸한다

  • Vault 이체 (Vault Transfer) ↗

    워크스페이스 vault 사이에서만 도는 이동

  • 웹훅(Webhook) ↗

    무엇이 언제 오고 무엇을 하면 되는가

  • 출금 (Withdrawal) ↗

    워크스페이스 vault에서 외부로, 그리고 계정 지갑의 오입금 반환

정책·서명 22

  • 정책 ↗

    서명 앞의 검사 단계

  • 구조 ↗

    무엇이 어디에 배포되고 각자 무엇을 지는가

  • 다이어그램 ↗

    정책 엔진의 배포 토폴로지·서명 게이트·상태 머신·발행 워크플로우와, rego·JSON 소스 구성, 코드 레벨 호출 경로를 상호작용 뷰어로 봅니다

  • 전체 지도 ↗

    저작 산출물이 가는 세 경로와 평가 입력의 조립, 두 장으로 요약한 정책 엔진

  • 운영과 관측 ↗

    fail-closed는 조용합니다

  • 결정과 결합 ↗

    여러 룰이 다른 답을 낼 때

  • 룰 명세 ↗

    룰이 무엇을 가리킬 수 있고 무엇이 그것을 검사하는가

  • 룰 구조 ↗

    룰은 네 조각입니다

  • 평가의 순간 ↗

    입력 문서가 조립되고 커널이 슬롯을 풀어 결정을 내리기까지

  • 정규화 ↗

    승인한 것과 서명될 것이 같은가

  • PIP ↗

    세상의 상태를 언제 어떻게 읽는가

  • 저장과 이동 ↗

    각 산출물이 어디에 저장되고 무엇이 네트워크를 오가는가

  • 승인 게이트 ↗

    어드민 액션과 정책 변경이 거치는 maker-checker

  • obligation 수집 ↗

    통과 조건으로 붙은 이행을 어디서 모으나

  • 비동기 수집 ↗

    파트너의 답을 기다리는 동안 요청은 어디에 있나

  • 서명 게이트 ↗

    판단과 집행이 두 단계로 나뉩니다

  • 서명 상한 대조 ↗

    승인 스탬프는 서명 직전에 일합니다

  • 금지선 ↗

    deny는 어떤 허가로도 뒤집히지 않습니다

  • 권한 상승 게이트 ↗

    하한 룰은 조건 없이 적용됩니다

  • 룰 변경 게이트 ↗

    정책을 바꾸는 요청도 정책 평가를 거칩니다

  • 출금 화이트리스트 ↗

    조건 하나가 수집 루프 전체를 발동합니다

  • 룰 저작과 발행 ↗

    draft 하나가 편집·검증·승인을 거쳐 활성 번들이 되기까지
