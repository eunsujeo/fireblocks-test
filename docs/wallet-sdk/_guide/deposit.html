입금과 집금 (Sweep)

고객 입금은 온체인 확정 후에도 동결 상태로 남습니다. 심사를 마친 입금 건을 지정해 WorkspaceVault로 집금합니다.

이 페이지 목차
집금 대상과 목적지처리 순서Sweep 요청상태와 완료 기준재시도와 미지원 기능

집금 대상과 목적지

고객에게 발급한 AccountWallet과 연결된 accountId·tokenId·네트워크·주소가 필요합니다. Sweep의 목적지는 WorkspaceVault ID입니다. 어떤 Vault를 출금 풀이나 보관용으로 사용할지는 파트너가 정합니다.

파트너는 입금의 고객 귀속과 심사 결과를 관리합니다. 주소록·트래블룰 정보가 일치한다는 사실만으로 SDK가 자동 해제하거나 자동 Sweep하지는 않습니다.

참고: 입금 (Deposit) ↗ · 자금 동결 ↗ · 집금 (Sweep) ↗

처리 순서

  1. SDK가 입금을 관측합니다

    DEPOSIT_DETECTED를 받으면 입금 건을 기록합니다. 이 시점은 온체인 확정 전입니다.

  2. 네트워크 기준에 따라 확정됩니다

    DEPOSIT_FINALIZED의 이벤트 상태는 FINALIZED이지만 SDK 내부 입금 상태는 FROZEN입니다. 동결은 SDK DB의 사용 제한이며 온체인 토큰의 동결 기능을 뜻하지 않습니다.

  3. 파트너가 입금 처리 여부를 판단합니다

    필요한 출처 확인·심사를 마친 뒤 depositId와 목적지 Vault를 지정하여 Sweep을 요청합니다. 트래블룰·KYT 연계에는 아래 미구현 제약이 있습니다.

  4. SDK가 정책 판단을 받고 입금 건을 선점합니다

    FROZEN이고 진행 중인 이동이 없는 입금 건만 조건부로 갱신합니다. 입금 한 건에 동시에 두 개의 이동이 진행되는 것을 막는 조건입니다.

  5. 인가받은 내용으로 서명하고 송금합니다

    서명 인프라가 제출한 실제 서명 대상을 일회용 인가와 대조합니다. SWEEP_INITIATED는 집금 시작 알림입니다.

  6. SWEEP_FINALIZED로 집금 완료를 확인합니다

    집금의 온체인 완료를 확인하고 파트너 원장에 업무 정책대로 반영합니다. 내부 WITHDRAWN 표시만으로 완료 처리하지 않습니다.

DB 처리와 온체인 전송

입금 선점과 해제 회계는 DB에서 묶어 처리할 수 있지만, 온체인 송금까지 같은 트랜잭션으로 확정되지는 않습니다. 실제 송금 결과는 이동 상태와 완료 이벤트로 확인합니다.

참고: 입금 (Deposit) ↗ · 집금 (Sweep) ↗ · 자금 동결 ↗ · 웹훅(Webhook) ↗

Sweep 요청

POST요청 예시
POST /api/v1/sweeps
X-API-KEY: <발급받은_API_키>
Idempotency-Key: <요청_식별자>
Content-Type: application/json

{
  "depositId": "<확정된_depositId>",
  "destinationVaultId": "<목적지_wv_ID>",
  "referenceId": "sweep-job-0001"
}

201 응답의 sweepId를 저장합니다. 금액은 지정한 입금 건에서 가져오므로 요청에 amount를 넣지 않습니다. Idempotency-Key는 필수 헤더이며, 응답 유실 시에는 referenceId로 조회합니다. 여러 입금을 묶는 온체인 배치 구성은 이 API 명세에서 확인할 수 없습니다.

파트너 API는 요청 생성 시 201을 반환합니다. 정책 엔진의 내부 접수 응답은 202이며, 이후 비동기로 평가합니다. 송금 완료 여부는 SWEEP_FINALIZED로 확인합니다.

GET요청 예시
GET /api/v1/sweeps?referenceId=sweep-job-0001
X-API-KEY: <발급받은_API_키>

참고: 스윕 요청 생성 ↗ · 스윕 referenceId 조회 ↗ · 서명 게이트 ↗

상태와 완료 기준

보이는 신호의미파트너 처리
DEPOSIT_DETECTED입금 감지관측 기록. 확정 입금과 구분
DEPOSIT_FINALIZED / 내부 FROZEN온체인 확정 / 사용 제한 유지귀속·심사 판단. 사용 가능 잔액과 구분
내부 WITHDRAWN원문상 Sweep 접수 단계에서도 등장하는 상태단독으로 집금 완료를 판단하지 않음
SWEEP_INITIATED송금 시작sweepId로 계속 추적
SWEEP_FINALIZED집금 완료중복을 제거하고 원장에 반영
SWEEP_FAILED집금 실패실패 사유와 최신 상태 확인. 원문상 입금은 FROZEN으로 복귀

원장 반영 시점

입금 표시, 사용 가능 잔액 전환, 집금 완료 기록의 시점은 파트너의 원장 정책으로 정합니다. 각 시점에 사용할 SDK 이벤트를 연결해 두어야 합니다.

참고: 입금 (Deposit) ↗ · 집금 (Sweep) ↗ · 웹훅(Webhook) ↗

재시도와 미지원 기능

응답을 받지 못했으면 referenceId로 기존 Sweep을 조회합니다. 같은 값으로 다시 요청해도 기존 집금을 반환하는 계약입니다. 새 referenceId를 발급하기 전에는 이전 요청의 결과부터 확인합니다.

트래블룰·KYT 연동 미구현

입금에 트래블룰·KYT 정보를 결합하는 기능과 DEPOSIT_UPDATED 통지는 아직 구현되지 않았습니다. 현재 입금 이벤트만으로 이 정보를 얻을 수는 없습니다. 목적지 Vault의 용도 태그를 검사하는 PIP도 미구현입니다.

AccountWallet 입금은 Sweep 또는 반환으로 소비합니다. WorkspaceWallet 입금은 별도의 전액 해제 경로를 사용합니다.
