# 원장 v0.1.4 HTML 문서 제작 계획

작성일: 2026-09-11. 대상 독자는 자금 흐름과 연동 방법을 파악하는 설계·개발자다.
기준 자료는 [원장_v0.1.4.pdf](../원장_v0.1.4.pdf), 화면 기준은 [Wallet SDK 가이드](../wallet-sdk/index.html)다.
2026-09-11 제작·브라우저 검증 완료. [HTML 문서](index.html)를 직접 열어 사용한다. ZIP은 제공하지 않는다.

검증: 업무 13개·상세 단계 31개·원문 순번 291개, 정의 10개·원문 64쪽을 포함한 HTML 94개를 생성했다.
내부 링크 1,885개, 기능 시나리오 19개, 데스크톱·모바일 화면 검사 188개를 통과했다.
한글·공백 경로로 옮겨 실행했으며 외부 요청·콘솔 오류 0건이다. PDF 해시, 원문 텍스트와 렌더링 이미지 보존을 확인했다.

## 방향

64쪽의 슬라이드를 업무별로 읽을 수 있는 HTML 문서로 재구성한다. 먼저 전체 구조를 보고,
업무 흐름 안에서 처리 순서·잔고 변화·관련 테이블을 확인한다. 용어와 상세 정의는 모달로 열어
읽던 위치를 유지한다. 원문 페이지도 같은 방식으로 확인할 수 있게 한다.

Wallet SDK 문서의 색상·글자 크기·탐색·검색·참고 모달을 재사용한다. 원장은 API 목록보다
업무 단계와 원장 갱신 관계가 중심이므로 본문 형식은 새로 구성한다.

## 본문과 상세 화면

- **업무 페이지**: 목적·시작 조건 → 참여 시스템과 자금 경로 → 단계별 처리 → 잔고 변경표 → 관련 정의와 원문.
- **단계별 처리**: 한 업무의 시작·감지·확정 등을 연속해서 읽는다. 각 단계에는 원문 순번,
  처리 주체, 요청/이벤트, 변경되는 테이블·필드, 증가/감소 또는 상태 변경을 표시한다.
  해당 단계에서 바뀌는 요소를 강조한 도식을 제공하고, 전체 단계도 함께 펼쳐 볼 수 있게 한다.
- **원장·테이블 상세**: 원문 명칭, 소유 주체, 키, 필드 의미, 갱신 업무, 이력·스냅샷 관계를 정리한다.
  원문에 없는 물리 테이블명·자료형·제약조건을 만들어 넣지 않는다.
- **용어·테이블 참고**: 로컬 HTML 모달로 열고 내부 이동·뒤로 가기·스크롤 복구·새 창 열기를 제공한다.
  가이드에서 바로 PDF나 외부 사이트로 이동시키지 않는다.
- **원문 확인**: 해당 PDF 페이지를 미리 렌더링한 이미지와 추출 텍스트로 제공한다.
  모달에서 확대할 수 있고, 원본 PDF 열기는 별도의 명시적인 동작으로 둔다.
- **검색**: 업무명, 테이블·필드명, 용어, TID/BCTX/Confirmed/Finalized 등 원문 용어와 한글 표현으로 찾는다.
  검색 결과는 해당 단계 또는 상세 화면으로 연결한다.

예를 들어 입금 페이지에서는 사전 통보(p.30), 감지(p.31), 확정(p.32)을 이어서 읽고,
`주소별 잔고`를 누르면 p.11의 필드 정의를 모달로 확인한 뒤 같은 입금 단계로 돌아온다.

## 원문을 옮기는 기준

- v0.1.4의 용어·순서·수식·증감 방향·주석을 기준으로 작성하고, 각 설명에 원문 페이지를 연결한다.
- 도식의 선 방향·점선·순번은 렌더링한 원문과 대조한다. 텍스트 추출 순서를 업무 실행 순서로 사용하지 않는다.
  초기 추출에서 PDF 숫자 형식 경고가 발생했으므로 페이지별 이미지·추출 텍스트를 함께 확인한다.
- DAWBC 등 설계자 명칭을 본문에 유지한다. BCM과의 대응은 기존 사용자 결정임을 별도 안내하며,
  이 문서의 내용을 현재 BCM에 구현된 기능으로 표시하지 않는다.
- 이번 버전의 전체 구조와 시퀀스에는 큐가 있다. 과거의 all sync 관련 설명을 그대로 적용하지 않는다.
  큐가 있다는 이유만으로 재시도·중복·역순·동시성 처리가 설계됐다고 보충하지도 않는다.
- 원문에 없는 실패·복구 시나리오, 불명확한 필드 정의나 식은 해당 페이지를 붙여 확인 사항에 기록한다.
  누락이나 모순이 의심되더라도 원문을 조용히 수정하지 않는다.
- 현재 버전만 읽기 화면에 제공한다. 과거 PDF는 기존 위치에 유지하고 버전 비교 페이지는 이번 제작 범위에 넣지 않는다.
- 원문의 버전과 `Strictly Confidential` 표기를 HTML 문서에 유지한다.

## 제작 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1. 원문 목록화 | 64쪽의 제목·도식·표·주석을 목록화하고 업무/테이블/용어에 연결 | 모든 페이지의 반영 위치 또는 표지·구분 페이지 여부가 기록됨 |
| 2. 대표 화면 제작 | 시작 화면, 입금 흐름, 주소별 잔고 상세, 원문 모달을 우선 제작 | 입금 p.30~32를 연속해서 읽고 p.11 정의를 확인한 뒤 읽던 위치로 복귀 가능 |
| 3. 전체 본문 작성 | 13개 업무, DB 정의, 대사식과 주소 관계 작성 | 시퀀스 순번·필드·증감·수식·각주가 원문과 대응하고 미명시 내용은 구분됨 |
| 4. 탐색과 UI 마무리 | 검색·단계 강조·모달 이력·새 창·모바일·인쇄 적용 | 링크 왕복 없이 관련 정의를 확인하고 키보드와 모바일로 탐색 가능 |
| 5. 원문 대조·실행 검증 | 페이지 매핑 검사, 도식 시각 대조, 브라우저 확인, 로컬 index.html 직접 실행 | 외부 요청 없이 실행되며 깨진 링크·이미지·수식·콘솔 오류가 없고 원본 PDF 해시가 동일함 |

2단계 대표 화면을 먼저 완성해 내용 밀도와 탐색 방식을 확인하고 같은 형식을 전체 업무로 확장한다.
문구는 짧은 기술 설명으로 쓰고 반복적인 도입 문장·장식용 카드·불필요한 배지를 줄인다.

## 산출물과 유지 방법

- `docs/ledger/index.html`: 문서 시작 화면.
- `docs/ledger/`: 업무별 HTML, 상세 참고 화면, 원문 페이지 보기, 도식·스타일·검색 자료.
- `scripts/ledger/`: 구조화한 문서 내용, 원문 페이지 매핑, 생성·검증 도구. 생성 HTML과 편집 원본을 구분한다.
- `docs/README.md`: 완성한 HTML 문서로 연결하는 입구 한 줄.

서버 없이 `file://`로 실행하고 스크립트와 검색 데이터는 HTML에 포함한다. 폰트·도식 등 리소스는
문서 폴더에서 읽는다. 기존 Wallet SDK의 화면·모달 구현을 활용하되 SDK 문서 자체의 동작은 바꾸지 않는다.
새 PDF를 받으면 페이지 매핑과 변경된 내용을 갱신해 HTML을 다시 생성할 수 있게 한다.

이번 계획은 설계자 문서를 읽기 쉽게 만드는 작업이다. BCM 코드·DB·API 계약 변경과 설계 타당성에 대한
별도 전면 리뷰는 포함하지 않는다. 제작 중 발견한 검토 필요 사항은 근거 페이지와 함께 남긴다.
