SC통화 SC자산 BC
잔고 등식
통잔(SC통화 잔고) = f입금 - f출금 자잔(SC자산 잔고) = f입금 - f출금 온잔(온체인 잔고) = c입금 + f입금 - c출금 - f출금
환잔(온체인 환산 잔고) = 온잔 - c입금 + c출금
통잔 = 자잔 = 환잔
가수금포함 잔고 등식
통잔 + 별단.입금완료 + 별단.송금중
= 자잔 (자잔에는 이미 f입금으로 포함됨)
= 환잔 (온잔에는 이미 f입금, c출금으로 포함됨)
델타원장 포함 잔고 등식
통잔 (통잔에는 이미 델타원장이 반영됨)
= 자산 - (TO: KB) + (TO: USER)
= 환잔 - (TO: KB) + (TO: USER)
델타정산 포함 잔고 등식
통잔 + 델정입금대기 - 델정송금대기 자잔 + 델정입금대기 - 델정송금대기 환잔 (온잔에는 델정입금대기와 델정 송금대기가 반영됨)
통잔 자잔 환잔 - 델정입금대기 + 델정송금대기
크로스브릿징 (고객상태 & 카뱅상태 변화는 아토믹, 크입과 크송의 수량은 동일함)
*외부브릿징과 크로스브릿징 방식의 차이가 생기는 이유: 외부브릿징은 실제 외부 업체에 카뱅보유의 자산을 전달함. (Mint/Burn과 동일하다고 생각됨). 그래서 SC통화에서 삭제되었다가
다시 나타나는게 맞다고 생각됨. 하지만 크로스브릿징은, 실제 자산은 카뱅에 존재하고 (마치 델타원장처럼) 받을 예정이기 때문에, 대사에 반영함. 하지만, 외부브릿징도 같은 방식으로
SC자산에서 같은 방식으로 처리할 수 있지 않을까? 아무리 생각해도, 실제로 자산이 빠졌고, 모든 대사에서도 깔끔하게 빠졌다. 외부브릿징중은 오직 카뱅의 자산 총합을 계산할때만
사용된다. 그러므로 현재의 방식이 맞는것 같다.
