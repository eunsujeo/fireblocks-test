이미지에 포함된 개요 설명 · p.50

한 SC통화에 대해 여러 BCTX가 생길 수 있다. • 예를 들어 '고객->카뱅 USDC 100' 이라는 하나의 정산에 대해, - ETH-USDC 보내는주소합 60, BASE-USDC 보내는주소합 80 이 있음 - ETH-USDC 보내는주소A 10, ETH-USDC 보내는주소B 20, ETH-USDC 보내는주소C 30, BASE-USDC 보내는주소A 25... 이렇게, 하나의 SC통화의 유동성은 실제 주소레벨에서는 분산되어 존재하기 때문에, 한 정산에 대해 여러 BCTX가 생길 수 있음 • BCTX 한개가 확정될때, 기존에는 SC자산과 SC통화 쪽도 모두 업데이트 했지만, 여기서는 모든 BCTX가 확정되지 않은 경우에는, DAWBC 쪽에서, 델타정산입금대기, 델타정산송금대기 항목에 해당 내용을 저장한다. • 마지막 BCTX가 확정된 순간, 델타정산입금대기, 델타정산송금대기 내용을 감소시키면서, 델타원장과 SC통화 쪽 모두를 업데이트 한다 델타정산 순서 • 시작: 델타원장 네팅 후, 생성된 여러 BCTX 서명 후 전파 • 컨펌: BCTX 컨펌 (txHash 건건마다 처리됨) • 확정: BCTX 확정 후 델타원장 등 수정 (모든 txHash가 확정되었을때, 델타원장의 상태가 정산완료로 변경됨)
