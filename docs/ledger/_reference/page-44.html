이미지에 포함된 개요 설명 · p.41

고객의 핫월렛에 부족한 SC자산(a)을 고객의 콜드월렛에서 가져오면서, 핫월렛에 남는 SC자산(b)을 콜드월렛에 보내는 연산 • a와 b는 같은 SC통화여야 한다 • 콜드월렛의 서명에는 시간이 걸린다. 그래서 콜드월렛 서명을 먼저 받고 진행한다. • 콜드월렛은 항상 80% 이상의 자산을 보관해야 한다. 그래서 콜드월렛 서명을 먼저 받고, 나중에 블록체인 네트워크로 전파한다. 브릿징스윕 순서 (고객.보내는주소의 ETH-USDC <-> 고객.콜드월렛 BASE-USDC). 반드시 콜드월렛 서명이 가능한 시간이어야 함 1. 시작: aBCTX(콜드월렛->보내는주소 BASE-USDC) 서명 후 저장, bBCTX(보내는주소->콜드월렛 ETH-USDC) 서명 후 전파 2. 보내는주소 컨펌: bBCTX(보내는주소->콜드월렛 ETH-USDC): Confirmed 3. 보내는주소 확정: bBCTX(보내는주소->콜드월렛 ETH-USDC): Finalized 4. 콜드 시작: aBCTX(콜드월렛->보내는주소 BASE-USDC)를 전파 5. 콜드 컨펌: aBCTX(콜드월렛->보내는주소 BASE-USDC): Confirmed 6. 콜드 확정: aBCTX(콜드월렛->보내는주소 BASE-USDC): Finalized
