# AI 프롬프트 가이드 — 작업 요청 요령

> 이 저장소에서 Claude Code 에 작업을 시킬 때의 요청 템플릿과 원칙.
> AI 쪽 규율은 [CLAUDE.md](../../CLAUDE.md) 6절 — 이 문서는 **사람이 요청을 쓰는 법**.

## 원칙

1. **설계 문서를 지목한다.** "출금 API 만들어줘" 보다 "docs/api/openapi.yaml 의 submitTransaction 계약대로" — AI 가 설계 대신 발명하는 것을 막는다.
2. **완료 기준을 준다.** "…하고, 전이 표 테스트가 그린이면 완료" — 기준이 없으면 AI 가 스스로 완료를 선언한다.
3. **범위를 닫는다.** "이 Phase 만, 다음 Phase 건드리지 마" — 세로줄 단위 유지.
4. **모르는 것은 모른다고 답하게 한다.** 벤더 동작이 확인 안 된 영역이면 "QnA 에 없으면 구현하지 말고 물어봐" 를 붙인다.

## 요청 템플릿

```
[작업] <한 줄 — 무엇을>
[설계] <근거 문서 — 예: docs/design/02-bcm-flow.md 허용 전이 표>
[범위] <이번에 만들 것 / 건드리지 않을 것>
[완료 기준] <통과해야 할 테스트·동작>
```

예:

```
[작업] 판단 워커의 전이 판정 구현
[설계] docs/design/02-bcm-flow.md 허용 전이 표 (표의 행 그대로)
[범위] domain 모듈만. 인박스 폴링·outbox 적재는 다음 작업
[완료 기준] 전이 표 전 행 단위 테스트 + FINALIZED→CONFIRMED 무시 케이스
```

## 리뷰 요청

"리뷰해줘" 는 다음을 모두 포함한다:

- 레이어 규칙 위반 (domain 에 Spring 의존, api 에 비즈니스 로직)
- 확정 결정 위반 (outbox 우회, txId dedup, 배치 sweep 부활 등)
- 계약 로직의 테스트 누락
- 추측으로 쓴 벤더 동작 (근거 문서 없는 필드·순서 가정)

전용 리뷰 agent: `.claude/agents/code-reviewer.md` — `code-reviewer 에이전트로 리뷰해줘` 로 호출.
